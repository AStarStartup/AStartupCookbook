### Reward Loops

For operating a startup, use a reward loop as a practical description: a cue prompts an action, and its result provides feedback for the next action. This is a management model, not a claim that a notification produces a particular dopamine response or that variable rewards inevitably create addiction.

#### Choose an honest result

Write down the user's goal, the action, the feedback, and the outcome you can check. A green checkmark is useful only if its test covers the intended behavior. A closed ticket is useful only if the problem is resolved. Revenue, retention, accuracy, and support burden must have defined units and time periods.

Avoid paying yourself or an agent for lines of code, commit counts, time in an app, or other proxies that can increase while customer value falls. Use a small number of outcome checks and inspect exceptions.

#### Founder practice

Break a large task into reviewable units with real results. Leave a short log of what worked, what failed, and the next action. A useful research unit can end in evidence that stops a bad build. Do not make meaningless commits or hide blocked work to create a feeling of progress.

A founder may build, sell, support customers, and direct agents. Delegation does not eliminate accountability or the work that only the founder can do.

#### Product ethics

Give users clear progress, notification controls, and a way to stop. Measure whether they accomplish their chosen task and understand the result. More checking or scrolling is not proof of usefulness. Do not hide costs or use distress as an engagement tactic. Claims about compulsion require evidence and qualified review beyond this operating model.

#### Agent feedback is not weight training

A coding agent can read a failed test, revise a draft, and rerun the check. This changes the workflow's next attempt; ordinary local inference does not update model weights. Persistent files or retrieval can preserve information when actually loaded, but they are not fine-tuning or reinforcement learning.

A test suite can miss defects and can be manipulated. Review the tests and the critical user journey as well as the pass count.
